# Next.js 16.4.2: the dev server no longer starts without its deepest routes

**What** — Next.js 16.3.8 → 16.4.2 (`apps/web/package.json`, lockfile), and an
E2E start-up check that the server answers its deepest routes.

**Why** — About 1 in 70 CI runs (9 since 23 Aug; 8 Oct on #146, 18 Oct on main
da5b422d), every E2E request to a route 7 or more folders deep under `src/app`
got Next's HTML 404 for the whole run: `identity/self/[action]`,
`hr/actions/[action]`, `hr/payroll/[runId]/wps` and the like. Their 6-deep
siblings `identity/[action]` and `hr/[resource]` worked. 48 specs failed on a
password change.
- **Cause:** a startup race in `next dev` up to 16.3. The route table is built
  from a Watchpack scan with a 5 ms aggregate timeout, and a handler run on a
  partial scan can overwrite a later complete one. Nothing under `src/app`
  changes in CI, so nothing repairs it.
- **Upstream:** vercel/next.js#97897, fixed by #97920. First released in
  16.4.0; no 16.3.x carries it.
- **Bonus:** 16.4.1 also patches GHSA-673q-mjm6-r5xr, GHSA-2464-fhr4-w9xw and
  GHSA-p3m5-59mp-jv5r. Production was not exposed to any of them: no `use cache`,
  no Server Actions, and `sharp` already at 0.35.5.

**Where**
- `apps/web/package.json`, `apps/web/package-lock.json`: `next`, `@next/env` and `@next/swc-*` at 16.4.2; nothing else moves.
- `apps/web/tests/e2e/globalSetup.ts`: `assertDeepRoutesServed()` GETs one route 6, 7 and 8 folders deep and fails the run at once on Next's HTML 404.

**Behaviour** — None for users. On 16.4.0+ the dev server waits until its first
scan is complete before it publishes routes. Strict route matching (on by
default in 16.4) only concerns `@slot`, catch-all and interception routes; this
app has none.

**Verified**
- A seven-agent investigation: Next internals, upstream issues, nine CI
  occurrences, and a route-matching replay with Next's own helpers (0 unmatched
  URLs; removing only `identity/self/[action]` reproduces the failing run). Two
  skeptic reviews did not refute it.
- `npm audit --omit=dev`: 0 vulnerabilities.
- CI on this branch: typecheck, lint, unit, integration, E2E and `next build`.

**Left open** — Watch staging after release. 16.4 has two open dev-only reload
loops (#100251, #100267); neither applies to CI or production.
