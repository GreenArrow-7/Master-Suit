# One register, so "has a commit" stops reading as "done"

## What

[docs/qa/REGISTER.md](../docs/qa/REGISTER.md): every open item with its SHA and
four separate columns — implemented, tested, deployed, live-verified — plus the
CI position for each head on this branch.

## Why

Across this work the same three things kept being conflated: a commit existing,
its tests passing, and a user's phone behaving. They are not the same claim and
collapsing them is how "fixed" gets said too early.

One reconciliation in particular needed writing down. **The assignment-scope
fix has never passed CI.** Its only run (`34f969f8`) was cancelled by the next
push. `6ca4e589` is green and is an _ancestor_ that does not contain it. A green
ancestor is not evidence for a later head, and the register says so rather than
leaving the inference available.

## Where

- `docs/qa/REGISTER.md` — new.

## Behaviour

No change.

## Verified

Every row read from `git`, `gh run list`, `gh pr view` or the operator's own
`docker exec` output — not from memory of earlier turns in the session.

## Left open

It is a snapshot and will go stale. The CI column especially: runs on this
branch are routinely cancelled by the next push, so the honest reading is
"what has a green run **on this exact SHA**", which is what the table records.
