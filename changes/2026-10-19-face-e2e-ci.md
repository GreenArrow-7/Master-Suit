# Face check-in is tested against the real face engine on every PR to main

**What** — A `face-e2e` job in CI starts the face sidecar, derives the test
frames and runs `tests/e2e/face-attendance.spec.ts` for real (M15-01, half b).
PR #232.

**Why** — M15-01's acceptance asks for the spec to run once with the sidecar and
its result recorded. It had always skipped in CI: the frames are never committed
(docs/TEST-DATA-POLICY.md) and `verify` runs no face service. Owner's brief:
build everything that needs no owner account.

**Where**
- `.github/workflows/ci.yml` — new `face-e2e` job, beside `verify`, on the same condition as its E2E (PRs to `main`, pushes to `main`); repeats verify's Postgres, Redis, object storage, migrations and seed, then `docker compose up --wait face`, the frames and the one spec.
- `apps/web/tests/e2e/face-attendance.spec.ts` — `FACE_E2E=required` turns the three skips into failures; adds a wrong-way head turn (liveness) and an off-site punch (geofence); 10-minute budget for a cold dev server.
- `apps/web/scripts/face-test-frames.mjs` — sources fetched from `upload.wikimedia.org`, pinned by SHA-256, retried on 429/5xx.
- `apps/web/scripts/verify.mjs` — counts named steps in the `verify` job only; the old count saw face-e2e's steps and refused to run.
- `docs/TEST-DATA-POLICY.md` — provenance row notes the CI use.

**Behaviour** — None for users. CI gains one job (about 3 min of runner time, in
parallel, so the wall clock does not grow). In it the sidecar is the Compose
`face` service: image built from `apps/face` (no layer cache, the build is
quick), buffalo_l weights fetched on first start from the pinned insightface
v0.7 release, a fresh random token for the run given to both sides. The three
source photographs are kept in the Actions cache, never in git.

**What the spec proves**, against the real engine:
- enrolment: refused with no consent (409), with three samples (409) and with
  four too-similar ones ("too similar"); accepted with four distinct poses;
- refusal of a different face: Mae Jemison turning as asked → `REJECTED_FACE`;
- the nonce is spent by that attempt: replaying it → 409;
- liveness: the enrolled face turning the other way → `REJECTED_LIVENESS`;
- geofence: the enrolled face turning as asked, 2 km from a 200 m site →
  `REJECTED_GEOFENCE`;
- match: the enrolled face turning as asked on site → `ACCEPTED`, "Checked in.";
- a second punch inside 60 s → `REJECTED_DUPLICATE`; after it → "Checked out.";
  the attendance day carries both times.
"Up" challenges are drawn again: no 2D warp of a still photograph moves the
pitch estimate enough.

**Verified**
- Locally on the ev rig with the sidecar in Docker (token on), cold `.next`:
  1 passed in 2.1 min. With the sidecar stopped and `FACE_E2E=required`: fails
  on 503 `face-engine-unavailable` instead of skipping.
- `docker compose up --wait face`: built and healthy in 1 min 42 s; `/analyse`
  without the token → 401.
- The frames script: fresh download, cached re-run (identical frames), and a
  tampered source refused by hash.
- `node scripts/verify.mjs --list` passes (main's copy exits 2 on this ci.yml);
  tsc, prettier, the unit folder.
- CI, PR #232 run 39198157211 (fd96257f): `face-e2e` green in 3 min 10 s.
  The image built in 11 s, the sidecar was healthy 6 s after it started, the
  sources downloaded on the cold cache, and the spec passed (1.6 min).
